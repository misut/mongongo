# mongongo v0.1.0 Release Notes

mongongo v0.1.0 is an early Kotlin Multiplatform MongoDB client release. It is
intended to be coherent and testable, not production-complete.

## Coordinates

- Group ID: `io.github.misut`
- Root artifact: `mongongo-core`
- Version: `0.1.0`
- Kotlin Multiplatform target artifacts:
  - `io.github.misut:mongongo-core`
  - `io.github.misut:mongongo-core-jvm`
  - `io.github.misut:mongongo-core-macosarm64`

## Scope

- BSON-first MongoDB OP_MSG command path.
- Typed CRUD helpers backed by a small kotlinx.serialization BSON codec.
- Explicit field-path filter and update DSL helpers.
- Sessions and transactions.
- Bounded `withTransaction` retries for server errors labeled
  `TransientTransactionError` and bounded `commitTransaction` retries for
  `UnknownTransactionCommitResult`.
- SCRAM-SHA-256 authentication, TLS URI options, and initial SRV resolution.
- Database and index helpers for common setup and smoke testing.
- JVM tests using fake OP_MSG servers and embedded MongoDB where useful.
- macOS Arm64 tests using fake OP_MSG servers plus optional real MongoDB smoke
  URIs.

## Validation

Local release-candidate validation should run:

```sh
mise exec -- ./gradlew :mongongo-core:spotlessCheck :mongongo-core:jvmTest :mongongo-core:macosArm64Test
mise exec -- ./gradlew :mongongo-core:check
mise exec -- ./gradlew :mongongo-core:publishToMavenLocal
git diff --check
```

External MongoDB smoke tests are optional and skip when their environment
variables are unset. The current environment variables are:

- `MONGONGO_TEST_URI`
- `MONGONGO_AUTH_TEST_URI`
- `MONGONGO_TLS_TEST_URI`
- `MONGONGO_AUTH_TLS_TEST_URI`
- `MONGONGO_SRV_TEST_URI`
- `MONGONGO_AUTH_SRV_TEST_URI`
- `MONGONGO_TRANSACTION_TEST_URI`

## CI

The repository has a minimal GitHub Actions workflow:

- Ubuntu JVM validation: Spotless check and JVM tests.
- macOS Arm64 validation: macOS Arm64 tests.

The macOS job uses the standard GitHub-hosted `macos-14` arm64 runner because
Kotlin/Native `macosArm64` tests require an Apple Silicon host.

## Publishing

The Gradle build configures Kotlin Multiplatform Maven publications for the
root metadata artifact, JVM artifact, and macOS Arm64 artifact. Local validation
uses `publishToMavenLocal` and must include sources and javadoc jars for each
publication.

Remote Maven publication is gated by release workflow secrets:

- `MAVEN_PUBLISHING_REPOSITORY_URL`
- `MAVEN_PUBLISHING_USERNAME`
- `MAVEN_PUBLISHING_PASSWORD`
- `SIGNING_IN_MEMORY_KEY`
- `SIGNING_IN_MEMORY_KEY_PASSWORD`

The workflow fails the publish job when any required secret is missing, and the
GitHub Release is created only after the Maven publish job succeeds.

## Known v0.1 Limits

- No connection pool. Each `MongoClient` owns one connection and serializes
  request/response traffic on it.
- No retryable writes.
- No causal consistency tracking for `operationTime` or `$clusterTime`.
- No aggregation or change streams.
- No custom TLS CA files or client certificates.
- No SCRAM-SHA-1, x509, AWS, GSSAPI, or PLAIN authentication.
- No SRV polling after connect.
- Typed serialization is intentionally small and rejects unsupported shapes.
